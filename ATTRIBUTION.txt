MODELS
------
Phase 0 default: NONE. The LLM wrapper ships with a deterministic offline stub
provider (`_StubProvider` in backend/app/ai/llm_client.py) so the repository
runs end to end with no API key and no network access. See DECISIONS.md D-010.

Optional live provider, used only when CARENOTE_LLM_PROVIDER=anthropic:
  Anthropic Claude (claude-sonnet-4-5) — commercial API, Anthropic Commercial
  Terms of Service. Not redistributed; accessed over the network at runtime.

PHASE 5 SPEECH-TO-TEXT: NO MODEL ADDED.

Ambient voice capture ships with a deterministic offline stub
(`_SimulatedProvider` in backend/app/ai/asr_client.py). It does not perform
speech recognition — it returns a fixed synthetic transcript keyed on the
audio's digest, and every capture it produces is flagged
`transcription_simulated = true` so no surface can imply otherwise
(DECISIONS.md D-046).

No speech-to-text model, model weights, or ASR service is bundled, downloaded,
or called. Two provider slots exist as documented interfaces with
NotImplementedError bodies:

  `local`   intended for faster-whisper / whisper.cpp (both MIT; OpenAI Whisper
            weights are MIT-licensed). NOT vendored and NOT downloaded by this
            repository. If implemented, add the library and the model weights
            here at that moment.
  `remote`  intended for a hosted recogniser. Gated behind
            CARENOTE_ASR_ALLOW_AUDIO_EGRESS and unimplemented; no vendor is
            configured, so no vendor terms apply to this build.

The model names appearing in configuration defaults (e.g. "whisper-large-v3")
are placeholder identifiers for an unimplemented path, not evidence that any
model was used.


PHASE 2 — NO NEW DEPENDENCIES
-----------------------------
Phase 2 added the entire product surface (timeline, AI scribe pipeline, Glance
View, collaboration, revision history) without adding a single new library to
either requirements.txt or package.json. Checked by reading the imports, not by
trusting the manifests.

Specifically:
  * Diffing uses difflib from the Python standard library, not a diff package.
  * Summarisation on the offline path is written in this repository
    (backend/app/services/scribe.py), not a summarisation library.
  * Typography uses system font stacks (ui-sans-serif, ui-monospace). No webfont
    is downloaded, so no font license applies and the build runs offline.
  * No Markdown renderer was introduced. This is deliberate and enforced by
    tests/test_sanitization.py, which fails the build if one appears in
    package.json without the raw-HTML-disabled review (DECISIONS.md D-015).
  * No charting, date, state-management or component library was added.


PHASE 3 — NO NEW DEPENDENCIES
-----------------------------
The four brief-named test files use pytest and the Python standard library

PHASE 4 — NO NEW DEPENDENCIES
-----------------------------
Both bonus tracks — self-learning importance and data decay — were built with
no new library in either manifest. Checked by reading the imports, not by
trusting requirements.txt.

Specifically:
  * Learned weights are arithmetic: math.pow for the evidence half-life and a
    saturating divide. No ML, statistics, or numerical library was added, and
    none is needed — the brief explicitly allows a weighted counter, and a
    dependency here would buy nothing but a larger install and a harder audit.
  * Archive compression uses zlib and base64 from the Python standard library.
    No compression package (lz4, zstandard, brotli) was added. zstd would give a
    materially better ratio on multi-KB notes and is the right call at real
    volume; it is a compiled dependency, and this prototype cannot demonstrate
    needing it. Recorded rather than silently skipped.
  * Extractive summarisation reuses services/features.py, which already exists
    for Glance View scoring. No summarisation library, and deliberately no LLM
    in the compression path — see DECISIONS.md D-043.
  * The learning transparency panel (frontend/src/components/LearningPanel.jsx)
    is plain React and Tailwind. No charting or visualisation library was added
    to render the weights.


DATA
----
All data in this repository is SYNTHETIC and was written by hand for this
project (backend/init_db.py, backend/app/services/transcripts.py, and the sample
strings inside tests/).

The consult transcripts in services/transcripts.py contain invented names,
NRIC-format identifiers and phone numbers. They are placed there deliberately so
that the redaction chokepoint has real identifiers to remove and the removal can
be demonstrated rather than asserted.

Phase 5 adds one more synthetic dataset: the simulated consult transcripts in
backend/app/ai/asr_client.py (_CLINICAL_CAPTURE, _PATIENT_CAPTURE). Every line
is invented. They contain a name placeholder, an NRIC-format identifier
(S8412345D) and a phone number (+65 6123 4567) that have never belonged to
anyone, planted so the redaction boundary has real identifiers to remove and the
removal can be demonstrated rather than asserted.

They also contain code-switched English/Malay clinical speech ("malam paling
sakit", "mahu pecah"). This is invented dialogue written to exercise per-segment
language tagging; it is not drawn from any corpus, transcript, or recording.

No audio file, voice sample, or speech corpus is included in this repository or
was used at any point. The build has never transcribed real audio.

Phase 4 adds one more synthetic dataset: the prior clinician interaction history
in backend/init_db.py (_seed_interaction_history). These are thirteen invented
InteractionLog rows representing six months of clinical attention in one clinic.

They are written as BEHAVIOUR, not as learned weights. The seed records the
interactions and then runs the same aggregation a live click runs; it does not
write FeatureWeight rows directly. Seeding the weights would have been shorter
and would have been a lie — the demo would show numbers no interaction produced,
in a build whose whole argument is that surfaced claims are traceable to their
source.

No external dataset is used. No real patient data has been used at any point,
and no real record was ever accessible to this system.

Patient names, clinic names, MRNs, NRIC-format identifiers, phone numbers and
dates of birth appearing anywhere in this repository are invented. The
NRIC-shaped strings in tests (e.g. S1234567D) are pattern-valid but do not
correspond to real identifiers.
